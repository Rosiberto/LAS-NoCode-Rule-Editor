# LAS-NoCode Rule Editor - Example: Temperature Monitoring Rule

This example demonstrates the use of the LAS-NoCode Rule Editor (LAS) for the visual creation and deployment of a simple **Complex Event Processing (CEP)** rule in an IoT scenario.

The workflow illustrates how LAS can be used as a low-code rule authoring environment, where rules are visually defined, automatically translated into EPL (*Event Processing Language*), and deployed to FIWARE Perseo CEP for execution.

The example also demonstrates a reproducible experimentation setup using containerized FIWARE components and simulated sensor events.

---

## Scenario

The objective is to define a CEP rule that detects temperature values above a predefined threshold.

- **Input:** Temperature events sent to Orion Context Broker by simulated sources.
- **Rule Condition:** `temperature > 30`.
- **Execution Engine:** FIWARE Perseo CEP.
- **Expected Behavior:** An alert is triggered whenever the condition is satisfied.

This example focuses on the rule authoring and deployment workflow provided by LAS, while Perseo CEP is responsible for runtime rule execution.

---

## 1. Rule Definition in LAS

Using the visual editor, the rule can be defined through block-based components representing conditions and actions.

[Condition: TEMPERATURE > 30] ---> [Action: GENERATE ALERT]

Once the rule is complete, LAS automatically generates the corresponding EPL rule and deploys it to Perseo CEP through its REST API.

- The **Condition Block** defines the event filtering criteria.
- The **Action Block** specifies the action executed when the condition is satisfied.

After the flow is completed, LAS automatically generates the corresponding EPL rule and deploys it to Perseo CEP through its REST API.

---

## 2. Automatically Generated EPL

The following EPL is generated from the visual rule definition:

```sql
SELECT temperature!
FROM iotEvent
WHERE temperature! > 30
```

The `!` notation follows the attribute reference syntax used by FIWARE Perseo CEP during EPL evaluation.

The generated EPL is deployed to Perseo CEP, which evaluates incoming events received from Orion Context Broker.

---

## 3. Event Processing Workflow

The event flow associated with this example is summarized below:

1. Simulated IoT devices send temperature events to Orion Context Broker.

2. Orion forwards notifications according to its configured subscriptions.

3. Perseo CEP evaluates the EPL rule generated by LAS.

4. When the rule condition is satisfied, the configured action is executed.

This architecture preserves the design-time/runtime separation adopted by LAS, where the editor is responsible for rule authoring and Perseo CEP handles event processing and execution.

## 4. Optional Event Simulation Script

For reproducible experimentation without physical devices, the following Python script can be used to generate temperature events:

```python
import requests
import random
import time

# Replace with your Orion Context Broker endpoint
ORION_URL = "http://localhost:1026/v2/entities/Room1/attrs"

HEADERS = {"Content-Type": "application/json",
           "fiware-service": "las", # change this to your FIWARE service
           "fiware-servicepath": "/"} # adjust service path if needed

i = 1
while i < 3:
    temp = random.randint(25, 35)

    event = {
        "temperature": {
            "type": "Number",
            "value": temp
        }
    }
    
    response = requests.post(ORION_URL, json=event, headers=HEADERS)
    print(f"Sent event: {event}, response status: {response.status_code}")

    i += 1
    time.sleep(1)
```

The script sends randomized temperature values to Orion Context Broker, enabling validation of the CEP rule execution workflow.

## 6. Reproducing the Example

To reproduce this workflow:

1. Start Orion Context Broker and FIWARE Perseo CEP using Docker containers.

2. Run LAS-NoCode Rule Editor using Docker or Docker Compose.

3. Create the visual rule in LAS.

4. Generate and deploy the EPL rule to Perseo CEP.

5. Execute the optional Python simulation script or submit events manually.

6. Observe rule evaluation and alert generation through Perseo CEP.
